# Архитектура

## Общий подход

Проект развивается как модульный монолит. Web, API и worker находятся в одном репозитории и могут работать на одном сервере, но доменные границы не смешиваются.

```text
apps/
  web/       Next.js: интерфейсы ученика, куратора и администратора
  api/       NestJS: REST API и бизнес-правила
  worker/    фоновые задачи и интеграции
packages/
  contracts/ общие схемы запросов, ответов и событий
  ui/        общие UI-компоненты
  config/    проверка конфигурации
prisma/
  schema.prisma
docs/
  adr/       архитектурные решения
```

## Доменные модули

- `auth`: вход, сессии, 2FA, passkeys, привязка Discord;
- `users`: профили и роли;
- `cohorts`: практикумы, потоки, зачисления и сроки доступа;
- `courses`: модули, уроки, материалы и прогресс;
- `assignments`: ДЗ, попытки, вложения, статусы и проверки;
- `scheduling`: конференции, места и записи;
- `media`: видео, файлы, права просмотра и водяные знаки;
- `notifications`: email и Discord-уведомления;
- `integrations`: внешние API и webhook-и;
- `audit`: журнал критичных действий.

## Границы

- Web не импортирует Prisma и не подключается к базе напрямую.
- Контроллеры не содержат бизнес-правил.
- Доменный код не зависит от Vimeo, Discord или конкретного HTTP-клиента.
- Внешние сервисы подключаются через adapters/interfaces.
- Основная база данных — PostgreSQL. Redis не используется как источник истины.

## Доступ

Права определяются ролью и зачислением в поток:

```text
user -> enrollment -> cohort -> course/content
```

Базовые состояния зачисления: `active`, `alumni_readonly`, `suspended`, `revoked`.

Куратор видит только назначенные потоки. Проверка выполняется на API-уровне для каждого объекта, а не только при отображении страницы.

## ДЗ

Каждая отправка — отдельная попытка. Рекомендуемые переходы:

```text
not_started -> draft -> submitted -> in_review -> needs_revision -> accepted
```

Комментарии, оценки и видеоразборы куратора привязываются к конкретной попытке.
