# Задания и проверка

## Серверный сценарий

- Куратор публикует задание через `POST /api/assignments`.
- API создаёт связь с практикумом, модулем и уроком, сохраняет критерии, допустимые форматы и число попыток.
- Ученик получает только опубликованные задания через `GET /api/assignments`.
- Отправка выполняется через `POST /api/assignments/:assignmentId/submissions`.
- Куратор получает очередь через `GET /api/review/submissions`.
- Решение по работе сохраняется через `PATCH /api/review/submissions/:submissionId` с `decision=accepted|revision`.
- Удаление задания является архивированием через `DELETE /api/assignments/:assignmentId`; отправленные работы не удаляются каскадно из интерфейса.

## Ограничение текущего этапа

Файлы ДЗ загружаются в приватное локальное хранилище через `POST /api/files`, `PUT /api/files/:fileId/content` и выдаются через `GET /api/files/:fileId/content`. В PostgreSQL сохраняются владелец, ключ, имя, тип, размер и связь с конкретной попыткой. Доступ к выдаче проверяется на API; публичных URL нет. Для production локальный адаптер нужно заменить на S3-compatible storage и добавить антивирусную проверку.

Все маршруты требуют серверную сессию. Публикация и проверка доступны `CURATOR`/`OWNER`, отправка доступна только активному `STUDENT`.

## История попыток для куратора

`GET /api/security/students/:studentId/assignments` возвращает одну запись на задание, а не отдельную строку на каждую отправку. Последняя попытка находится в полях `attempt`, `status`, `answerText`, `feedback` и `files`, полный хронологический список — в `attempts`. Поэтому повторная отправка и доработка не создают дубликат задания в профиле ученика.
