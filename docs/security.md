# Безопасность

## Аутентификация

- Для учеников использовать passwordless-вход, passkey или безопасную email-ссылку.
- Telegram и Discord являются привязками, а не единственным доказательством личности.
- Для кураторов и администраторов обязательна 2FA.
- Сессии хранятся в HttpOnly/Secure cookies или в серверном session store.
- Пользователь может увидеть устройства и завершить все активные сессии.
- Входы и изменения привязок записываются в audit log.

## Авторизация

- Принцип deny by default.
- Роль и область доступа проверяются отдельно.
- Нельзя полагаться на ID из URL, скрытую кнопку или фильтр в интерфейсе.
- Тестировать попытку ученика открыть чужое ДЗ, видео, профиль и поток.

## Файлы и видео

- Файлы хранятся в приватном S3-compatible bucket.
- Клиент загружает файл по короткоживущему signed URL.
- Проверяются размер, MIME, расширение, владелец и назначение файла.
- Для видео использовать приватный поток или embed с ограниченным доменом.
- Временные ссылки не сохраняются как постоянные права доступа.
- Для важных материалов использовать персональный водяной знак.
- Нельзя обещать полную защиту от записи экрана; цель — ограничить доступ и установить источник утечки.

## Секреты и данные

- Секреты только в env/secret storage.
- Не логировать пароли, токены, cookies, API-ключи и содержимое ДЗ без необходимости.
- Production-база не доступна из публичного интернета.
- Резервные копии шифруются и регулярно проверяются восстановлением.
- Для удаления пользователя определить правила удаления, анонимизации и хранения audit log.
