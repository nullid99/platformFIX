# Проверка кода

Ревью начинается с поиска проблем, а не с общего описания изменений.

## Порядок проверки

1. Сопоставить diff с исходным запросом и критериями приёмки.
2. Проверить изменение схемы БД, миграции и обратную совместимость.
3. Проверить права доступа для каждого нового endpoint-а и объекта.
4. Проверить ошибки, повторные запросы, таймауты и недоступность внешних сервисов.
5. Проверить загрузки файлов, приватность видео и утечки ссылок.
6. Проверить валидацию, пагинацию, индексы и N+1-запросы.
7. Проверить тесты успешных и отрицательных сценариев.
8. Запустить доступные автоматические проверки.

## Приоритеты замечаний

- **Critical:** обход авторизации, утечка секретов, потеря данных, опасная миграция.
- **High:** доступ к чужим данным, повторная операция с неверным результатом, поломка основного сценария.
- **Medium:** заметный регресс, отсутствие обработки ошибки, неправильное состояние интерфейса.
- **Low:** поддерживаемость, читаемость, локальная оптимизация.

Каждое замечание должно содержать файл, строку, причину проблемы и конкретный риск. Сначала перечисляются найденные проблемы, затем открытые вопросы и краткое резюме изменений.

## Что считается достаточным

Изменение принимается только когда:

- выполнены критерии приёмки;
- права доступа проверены отрицательными тестами;
- миграции безопасны;
- lint, typecheck и релевантные тесты проходят;
- в diff нет секретов, временных файлов и несвязанных правок.
