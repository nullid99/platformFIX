# Правила разработки

## TypeScript

- Включить `strict`, `noUncheckedIndexedAccess` и проверку unused-кода.
- Не использовать `any` для обхода типизации.
- Входные данные проверять схемами на границе API.
- Не доверять данным из браузера, Discord или webhook-а до серверной валидации.

## База данных

- Схема изменяется только через Prisma migration.
- Production не запускает автоматическую синхронизацию схемы.
- Статусы и переходы важных сущностей проверяются в транзакции.
- Уникальные ограничения и внешние ключи задаются в БД, а не только в коде.
- Для списков и журналов заранее определить пагинацию, сортировку и индексы.
- Данные и миграции должны быть совместимы с предыдущей версией приложения во время деплоя.

## API

- Единый формат ошибок.
- Явные DTO/request schemas и response types.
- Пагинация для коллекций.
- Idempotency key для повторяемых операций, где это необходимо.
- Rate limit для входа, загрузок, медиа и webhook-ов.
- Не возвращать лишние поля пользователя или внутренние идентификаторы без необходимости.

## UI

- Состояния loading, empty, error и forbidden должны быть предусмотрены явно.
- Кнопка не должна отправлять форму повторно во время запроса.
- Ошибки должны быть понятны пользователю, но не раскрывать внутренние детали.
- Доступные пользователю действия должны соответствовать серверным правам, но скрытие кнопки не заменяет серверную проверку.
- Формы должны корректно работать на мобильных экранах.

## Внешние сервисы

- Каждый внешний вызов имеет timeout, обработку ошибки и контролируемую повторную попытку.
- Webhook-и проверяют подпись, сохраняют `event_id` и не выполняются повторно.
- Токены внешних сервисов хранятся зашифрованными.
- При недоступности Vimeo или Discord основная учебная база не должна повреждаться.
